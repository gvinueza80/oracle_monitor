# Oracle Database Monitoring System

## Project Overview

A production-grade, real-time database monitoring platform for Oracle instances, providing web and mobile dashboards, alerting, and historical analysis.

## Technology Stack

### Backend
- **Framework**: FastAPI (Python 3.11+)
- **Async**: uvicorn with asyncio for concurrent database polling
- **Database Client**: cx_Oracle or oracledb (Python's official Oracle driver)
- **Data Storage**: PostgreSQL for metrics, alerts, and audit logs
- **Caching**: Redis for real-time metrics and session data
- **Task Queue**: Celery with Redis backend for async polling jobs
- **API Documentation**: OpenAPI/Swagger (auto-generated by FastAPI)

### Frontend (Web)
- **Framework**: Django 4.2+ with Django Rest Framework
- **UI Library**: React 18 with TypeScript
- **Styling**: Tailwind CSS
- **Charts/Metrics**: ECharts or Grafana plugin
- **State Management**: Redux Toolkit
- **Real-time Updates**: WebSocket via Django Channels

### Mobile (Cross-platform)
- **Framework**: Flutter 3.x
- **Language**: Dart
- **State Management**: Riverpod
- **Reasoning**: Single codebase for iOS/Android, native performance, excellent async support for real-time updates
- **Local Persistence**: Hive for offline caching

### Infrastructure
- **Containerization**: Docker & Docker Compose
- **Orchestration**: Kubernetes (optional, for scale)
- **Monitoring**: Prometheus + Grafana for system health
- **Logging**: ELK Stack (Elasticsearch, Logstash, Kibana)
- **CI/CD**: GitHub Actions

## Key Architectural Decisions

### 1. Real-time Data Architecture
- **Polling Strategy**: Tiered by metric type:
  - High-priority metrics (locks, slow queries): 5-10s intervals
  - Standard metrics (sessions, CPU): 30s intervals  
  - Trending data (capacity): 5-minute intervals
- **Push Updates**: WebSocket/SSE to clients for sub-1s perception
- **Redis Caching**: 30-90s TTL for frequently accessed metrics

### 2. Security Model
- **Authentication**: JWT tokens with 15-minute expiry
- **Authorization**: Role-based (Admin, DBA, Analyst, Viewer)
- **Credential Management**: Encrypted vault (HashiCorp Vault) for Oracle connection strings
- **Audit**: All database queries and config changes logged with user context
- **Network**: TLS for all connections; VPN/bastion host recommended for Oracle access

### 3. Scalability Approach
- **Multi-database Support**: Horizontally scalable collector agents per Oracle instance
- **Database Sharding**: Metrics partitioned by timestamp and instance for PostgreSQL
- **Distributed Caching**: Redis cluster for session sharing across API nodes
- **Rate Limiting**: Per-user and per-instance query limits

### 4. Data Retention & Compliance
- **Metrics**: 90-day retention, 1-hour aggregation beyond 7 days
- **Logs**: 1-year retention with encryption at rest
- **Purge Policies**: Automated cleanup with Celery Beat scheduler
- **Compliance**: GDPR-ready with user data export/deletion endpoints

## Known Challenges & Mitigations

| Challenge | Mitigation |
|-----------|-----------|
| Oracle connection pooling under load | Use cx_Oracle connection manager with tuned pool size |
| High-frequency queries overwhelming DB | Cache layer + adaptive polling intervals |
| Real-time sync across multiple clients | WebSocket broadcast with client-side deduplication |
| Mobile battery drain from constant polling | Background fetch API + intelligent backoff strategy |
| Credential exposure in logs | Sanitization filters + encrypted vault for secrets |

## Testing Strategy

- **Unit**: pytest for backend, Jest for React, test_flutter for Dart
- **Integration**: Docker Compose test environment with mock Oracle
- **E2E**: Playwright for web, integration tests for mobile
- **Load Testing**: k6 for API performance benchmarking
- **Security**: OWASP ZAP scanning, SQLi/XSS payload testing

## Deployment Considerations

- **Local Dev**: Docker Compose with mock Oracle container
- **Staging**: Kubernetes on cloud provider with test Oracle instance
- **Production**: Multi-region setup with health checks and auto-failover
- **Backup Strategy**: Daily PostgreSQL snapshots, Oracle WAL archived externally
